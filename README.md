# 가전운송계획 · 납품번호별 최초/최종 차량 비교 v2

기준: 2026-09-16 / Streamlit 앱 소스 패키지. 이 파일은 실제 배포된 사이트 주소가 아닙니다.

## 이번 변경

별도 입력양식을 작성하지 않고 **상세정보.xlsx(최초)**와 **최종리스트.XLSX(최종)**를 직접 올립니다.

| 최초 상세정보 | 최종리스트 | 사용 |
|---|---|---|
| 납품번호 | Delivery | 같은 납품건 연결 |
| 차량번호 | Vehicle Number(Full) | 최초 차량 → 최종 차량 비교 |
| 수량 | Qty(첫 번째 열) | 품목 수량 참고 비교 |
| 용적 (㎥) | Volume / VolumeUnit | 용적 참고 비교·단위 점검 |
| ZONE | 별도 셀 추정 없음 | 최초 ZONE 필터 |
| — | PDAStepStatus / PDAStatusTxt | 연기 판정 / 원문 설명 |

**기본 연기 코드: L, 7, 3, P.** 사용자 요청에 따라 네 코드를 모두 연기로 분류합니다. 원문에 Return, Cancellation 등이 있더라도 자동으로 별도 취소 분류로 바꾸지 않습니다. 원문 설명은 비교표에서 그대로 확인할 수 있습니다. 사이드바에서 분석 규칙을 바꿀 수 있으며 원본 코드는 수정되지 않습니다. 이 규칙은 사내 모든 시스템에서 통용되는 표준이라고 주장하는 것이 아닙니다.

## 실행·배포

### 기존 사이트를 업데이트할 때
이 폴더의 소스 파일들을 기존 저장소의 같은 위치에 교체합니다. 새 파일 `delivery_compare.py`, `delivery_ui.py`, `pair_storage.py`도 포함하세요. 실행 파일은 그대로 `app.py`입니다. `requirements.txt`를 갱신하고 앱을 재시작합니다. 기존 스냅샷 기능과 `dispatch_records` 저장내용은 유지됩니다. 새 기능은 별도 `delivery_datasets` 테이블을 생성하므로 초기 CREATE TABLE 권한이 필요합니다.

**원본 상세정보·최종리스트, CSV 비교결과, 백업·DB·비밀번호를 GitHub에 올리지 마세요.** 이 배포 ZIP에는 실제 업무자료가 없습니다. `templates/`에는 기존 빈 입력양식만 있습니다.

### 아직 사이트가 없을 때
Streamlit Community Cloud에 소스 저장소를 연결하고 실행 파일을 `app.py`, Python을 3.12로 지정합니다. 실제 주소는 배포 성공 후 해당 서비스에서 생성됩니다. 코드만 기본 배포하면 **가상 예시 모드**입니다. 실자료 업로드는 차단됩니다.

### 업무용 사이트
`.streamlit/secrets.example.toml`을 참고해 승인된 OIDC 로그인, 이메일 접근목록·편집자 목록, TLS PostgreSQL 접속정보를 설정하고 `mode="live"`로 사용합니다. 실제 Secrets는 저장소에 올리지 않습니다. 사용자 로그인 설정과 외부 DB 연결은 배포 환경에서 검증해야 합니다. 고객사별 분리 권한은 없으며 승인된 사용자는 같은 데이터셋을 봅니다.

### PC에서 실제 파일로 확인
Windows + Python 3.12: `run_local.bat` 실행. 브라우저에 Streamlit 화면이 열립니다. 최초 실행 때 패키지 설치용 인터넷 접속이 필요합니다. 로컬 테스트는 로그인 없이 `data/dispatch.db`에 저장하며 인터넷에 공개하면 안 됩니다.

명령 실행:
```bash
python -m pip install -r requirements.txt
# Windows CMD
set DISPATCH_LOCAL=1
python -m streamlit run app.py --server.address=127.0.0.1
```
macOS/Linux에서는 `DISPATCH_LOCAL=1 python -m streamlit run app.py --server.address=127.0.0.1`을 사용합니다.

## 화면 사용

1. 사이드바 **납품번호·차량이동 비교**를 선택합니다(기본 화면).
2. **원본 파일 등록**에서 상세정보와 최종리스트를 올리고 **두 파일 분석하기**를 누릅니다. 분석 직후는 미저장 미리보기입니다.
3. 납품번호 검색, 최초/최종 차량번호, 최초 ZONE, 매칭구분, 차량변경만, 연기만으로 조회합니다. 모든 표와 KPI는 같은 필터를 사용합니다.
4. **납품번호 조회**에서 최초 차량과 최종 차량을 나란히 확인합니다. 상세 납품번호를 선택하면 원본 Excel 행번호와 품목별 상태를 확인할 수 있습니다.
5. **차량 이동·반출입**에서는 최초→최종 차량별 이동 건수와 실제 납품번호 목록을 조회합니다. **연기 현황**은 코드별 고유 Delivery, **차량별 비교**는 차량별 건수·반출·반입·연기를 보여 줍니다.
6. **등록·검증 기준**에서 비교일을 확인하고 저장합니다. 같은 비교일의 최초 상세정보는 고정되며 다른 내용으로 덮어쓰지 못합니다. 최종 파일은 새 버전으로 누적됩니다.
7. 이후 저장한 비교일을 고르면 최초 파일 업로드는 생략하고 최종리스트만 새로 올릴 수 있습니다. 최종 파일의 과거 등록 버전도 선택 가능합니다.

## 집계 원칙

- 최종에는 품목 여러 행이 있으므로 Delivery별로 묶어 납품 1건으로 계산합니다. 행 수·품목 수량·납품건수·고객 방문수는 서로 다른 값입니다.
- 같은 납품건이 **차량변경이면서 연기**일 수 있습니다. 두 상태를 한쪽으로 덮어쓰지 않습니다.
- 최종에 없는 건은 **최종미존재**, 최종에만 있는 건은 **최종만 존재**입니다. 조회 범위 차이 가능성이 있어 자동 취소·연기·신규 확정으로 단정하지 않습니다.
- 기본 네 코드가 아닌 건은 **연기코드 아님**입니다. 이를 배송 완료·설치 성공으로 단정하지 않습니다.
- 최종 등재건수에는 연기건이 포함됩니다. 최종 차량의 연기를 별도 집계하며 등재 검산에서 두 번 빼지 않습니다.
- 차량별 검산: 최초 − 최종미존재 − 반출 + 반입 + 최종만존재 = 최종 등재건수.
- 복수 최종 차량·상충하는 동일 품목·상태 혼합·단위 누락을 확인사항으로 표시합니다. 복수 차량에서 납품건은 각 차량에 한 번씩 집계되므로 차량 합계와 전체 고유 Delivery 합계가 다를 수 있습니다.
- 품목 일부만 연기이면 **일부 연기(혼합)**로 구분합니다. 동일 품목의 정확한 중복은 수량 계산에서 제외하고 내용 충돌 시 수량을 임의로 정하지 않습니다.
- 최종 파일에는 Qty 열이 두 개 있으므로 **첫 번째 Qty**를 사용합니다. 고객 이름·주소·전화번호는 읽은 뒤 비교용 자료에 투영하지 않으며 저장하지 않습니다.
- 최초 파일의 정확한 완료시각이 없으므로 임의 생성하지 않습니다. DB 등록시각은 UTC 감사정보일 뿐 완료시각이 아닙니다. 비교일은 자료 분류용입니다.
- 첫 번째 파일과 마지막 파일만으로 중간 A→B→A 이동이나 정확한 이동시각을 복원할 수 없습니다. 이력 원본이 확보되면 기존 스냅샷·변경이력 메뉴에서 별도 관리합니다.
- 2026-09-17 배차판의 셀별 지정구역을 다른 날짜의 고정구역으로 재사용하지 않습니다. 이 화면은 최초 ZONE 원문만 표시합니다.

## 보관·보안

업로드는 앱 운영 서버로 전송되므로 회사가 승인한 호스팅에서만 사용하세요. 전역 공유 캐시에 원본을 저장하지 않으며 사용자별 미리보기와 권한 검사 후 저장을 구분합니다. DB에는 고객명·주소·전화번호를 제외한 비교용 필드와 등록자·등록시각·파일명·내용해시를 기록합니다. 데이터베이스 권한·백업·복구·보존기간은 운영자가 관리해야 합니다.

현재 비교의 JSON 백업은 분석용 원자료와 규칙을 보관하는 기능입니다. 이 v2 JSON을 자동 복구하는 업로드 UI는 포함하지 않습니다. 전체 DB 복구는 관리자의 DB 백업으로 수행하며, 원본 XLSX를 보관하면 앱에서 재등록할 수 있습니다. 최초 기준본을 잘못 저장한 경우 자동 삭제·수정 기능이 없으므로 운영자가 원본 검토 및 백업 후 조치해야 합니다.

## 검증 범위

`python -m unittest discover -v`로 기존 기능 18개와 새 납품번호 비교·저장 18개, 총 **36개 테스트**가 통과했습니다. 업로드된 실제 두 파일에서도 납품번호 매칭·상태 규칙·차량별 등재 검산을 확인했습니다. 실제 데이터는 이 코드 패키지에 포함하지 않았습니다.

작성 환경에서는 Streamlit 패키지 저장소에서 설치 패키지를 받을 수 없어 브라우저에서의 Streamlit 실제 실행은 검증하지 못했습니다. Python 구문 검사·비교 엔진·로컬 SQLite 저장 테스트는 완료했으나 클라우드 배포·OIDC·외부 PostgreSQL은 배포 환경에서 별도 확인해야 합니다.
